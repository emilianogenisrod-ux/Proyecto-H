2. ¿Qué es Proyecto H?

Es un sistema para organizar citas médicas: doctores, pacientes, horarios, citas, pagos y archivos (fotos o videos).

En la práctica sirve para:

  • Registrar doctores y pacientes
  • Definir en qué días y horas atiende cada doctor
  • Agendar, cancelar o reprogramar citas
  • Llevar el estado de los pagos de cada cita
  • Subir imágenes o plantillas relacionadas con el hospital

Piensa en una agenda de hospital compartida: cada persona ve lo que le corresponde según su puesto (administrador, director, doctor o paciente).

3. Cómo imaginar el sistema (sin código)

El mostrador

La pantalla web (lo que ves en el navegador) es el mostrador: botones, formularios y tablas. Tú pides cosas ahí.

La oficina de atrás

El servidor es la oficina que no se ve. Recibe tu pedido, revisa reglas (por ejemplo: “¿ese horario ya está ocupado?”) y responde.

El archivador

La base de datos es un archivador enorme y ordenado. Guarda doctores, pacientes, citas y pagos en “carpetas” llamadas tablas.

El almacén de fotos

Las imágenes y videos no viven en la misma carpeta que las citas: se guardan en un almacén de archivos (MinIO) y solo se anota en la base de datos “dónde están”. 

Tú (navegador)
   →  pides algo (por ejemplo: “lista de doctores”)
   →  el servidor lo entiende y busca en el archivador
   →  te devuelve la respuesta a la pantalla

5. Recorrido de un día normal

  1. Entras con tu correo y contraseña. El sistema revisa quién eres y te abre el panel correcto (admin, director, doctor o paciente).
  2. Ves tu pantalla de trabajo. Cada rol tiene botones distintos. Un paciente no administra doctores; un admin sí.
  3. Creas o consultas información. Ejemplo: agendar una cita. La pantalla manda el pedido al servidor.
  4. El servidor aplica reglas. ¿Existe el doctor? ¿El horario está libre? ¿El paciente existe? Si algo falla, te avisa; si todo va bien, guarda la cita.
  5. Se crea también el pago pendiente. Cada cita nueva nace con un cobro “en espera”, como una cuenta por pagar.
  6. Todo queda registrado. La próxima vez que abras el sistema, la información sigue ahí porque está en el archivador (base de datos).

7. Las “carpetas” de información (tablas)

En la base de datos, la información se guarda en tablas. Imagínalas como hojas de Excel con nombre:

Cómo se relacionan (como fichas que se apuntan)

  • Un doctor tiene muchos horarios y muchas citas.
  • Un paciente puede tener muchas citas.
  • Cada cita tiene un pago asociado.
  • Los medios guardan la ficha del archivo; el archivo en sí está en la bodega (MinIO).

8. Cómo se guarda y se lee la información

Cuando el sistema “crea una carpeta”, es como preparar una hoja nueva con columnas (nombre, teléfono, fecha, etc.). Eso se llama a veces CREATE TABLE, pero tú solo necesitas saber: define la estructura.

Cuando el sistema “busca datos”, es como filtrar esa hoja (“tráeme solo las citas de hoy”). Eso se parece a un SELECT.

Crear / guardar

Ejemplo mental: “Agrega un doctor nuevo llamado Ana”.

El servidor escribe una fila nueva en la carpeta de doctores.

Leer / consultar

Ejemplo mental: “Muéstrame todos los pacientes”.

El servidor lee la carpeta y te devuelve la lista a la pantalla.

En Proyecto H, casi todo eso lo hace el programa en Python de forma automática. Abajo verás ejemplos más técnicos por si alguien del equipo de sistemas los necesita.

10. Cómo se habla la pantalla con el sistema

Cada botón importante manda un pedido al servidor. Esos pedidos tienen dirección (ruta) y a veces datos (JSON, como una ficha rellenada).

Ejemplo en la vida real:

  1. En la pantalla de citas eliges doctor, paciente y hora.
  2. Pulsas “Guardar”.
  3. La pantalla envía un mensaje al servidor: “crea esta cita”.
  4. El servidor responde: “listo” o “no se puede, horario ocupado”.
  5. La pantalla se actualiza para que lo veas.

Si eres de sistemas y quieres probar pedidos a mano, usa la guía avanzada en /docs.

Se puede abrir en local para probar cambios antes de publicarlos.

En producción (internet)

La versión pública está en:

https://proyecto-h.iagentek.com.mx

Ahí el archivador es Supabase y la bodega de archivos es MinIO.

El equipo técnico conecta el sistema a esos servicios mediante configuración (como decirle al programa: “tu archivador está en esta dirección”). No hace falta tocar eso para usar el hospital digital día a día.

13. Fotos, videos y plantillas

  • Desde el panel (según tu rol) puedes subir imágenes, videos o plantillas.
  • El archivo se guarda en la bodega (MinIO) o, en pruebas locales, en una carpeta del proyecto.
  • En la base de datos solo queda la ficha: título, tipo, tamaño, quién lo subió y el enlace.
  • También puedes subir foto de perfil desde el menú del avatar.
